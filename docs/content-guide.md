# ✍️ Documentation and Interface Content Guide

## Writing principles

- Say what the code does today, not what a roadmap hopes it will do.
- Describe model predictions as uncertain category estimates, never objective suitability.
- Use plain language for privacy, security, and data handling.
- State accepted file formats accurately. The current PDF extension allowance is not PDF parsing.
- Do not promise deletion, confidentiality, encryption, compliance, fairness, or accuracy unless implemented and verified.

## Interface terminology

Prefer:
- “Predicted category” over “best career”.
- “Job listings for this category” over “personalized job matches”.
- “Experimental estimate” over “AI assessment”.
- “Use synthetic text for testing” over invitations to upload real résumés.

## Documentation review

For each change, check README, FAQ, privacy, model card, architecture, installation, and release notes for contradictions. Keep screenshots synthetic and free of secrets.
